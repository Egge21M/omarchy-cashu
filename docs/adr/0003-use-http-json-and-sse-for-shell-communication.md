# Use HTTP/JSON and SSE for shell communication

The Wallet Client uses versioned HTTP/JSON over loopback TCP for commands and canonical resource fetches, plus authenticated Server-Sent Events consumed by a shared Quickshell Shell Adapter as non-authoritative invalidation hints. The adapter projects its view from cocod's separate status, balance, mint, and operation resources; it refetches affected resources after an event and every relevant resource on startup or reconnect. V1 deliberately has no monolithic wallet snapshot, event revision, gap detection, or replay protocol. This works in stock Omarchy with authentication headers and no WebSocket dependency, but requires manual SSE parsing, reconnection, bounded server-driven stream rotation, and an integration test because repeated streaming callbacks are supported by Qt's implementation rather than guaranteed by its public QML API.
